# Launch++ v1 implementation roadmap

The detailed, source-controlled task plan is [`docs/implementation-roadmap.md`](../../docs/implementation-roadmap.md). This review surface summarizes its delivery boundaries, dependencies, and phase gates.

<Callout id="roadmap-mvp-decision" tone="decision">

**Phase 3 is the Launch++ MVP boundary.** Phase 2 proves the complete React/vanilla author loop under a preview contract. Phase 3 adds the capabilities serious plugins and small teams require: private durable collections, safe schema evolution, commands, inter-plugin dependencies, events/jobs, invitations, and roles. Marketplace and hosted-scale work remain post-v1.

</Callout>

## Scope guardrails

<Callout id="roadmap-scope-guardrails" tone="warning">

Do not pull marketplace billing, hosted scale, PostgreSQL, official Vue/Svelte/Angular tooling, microservices, Kubernetes-first deployment, arbitrary plugin SQL/Node access, or advanced project-management suites into v1. A deferred item needs measured demand or a demonstrated architectural limit before becoming committed work.

</Callout>

## Approval gate

Approve the phase boundaries, task order, Phase 2 author-preview boundary, and Phase 3 MVP definition before implementation begins. Execution should start with Phase 0 tasks in [`docs/implementation-roadmap.md`](../../docs/implementation-roadmap.md); completing documentation does not authorize skipping a feasibility or exit gate.
